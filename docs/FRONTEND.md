# 프런트엔드 명세 (web/)

백엔드 계약은 `docs/SPEC.md`(특히 3장 데이터 형식, 6.3 HTTP API)를 따른다. 이 문서는 화면의 구조와 동작을 정한다.
시각 디자인은 `design/`의 선정된 시안과 이 문서 끝의 "디자인 시스템" 절을 따른다.

## 1. 기술 제약

- 빌드 단계 없음. `web/index.html` + `web/assets/*.css` + `web/assets/js/*.js`(ES modules, `<script type="module">`).
- 외부 JS 라이브러리 금지. 웹폰트만 CDN에서 선택적으로 불러온다(실패해도 화면이 멀쩡해야 한다).
- 진행 상황은 **폴링**: `GET /api/runs/{id}/events?after=N&preview_from=K`를 1초마다(탭이 숨겨지면 3초), 종료 상태가 되면 멈춘다.
- **XSS 규칙**: `innerHTML`에 넣어도 되는 값은 서버가 만든 `report_html`, `answer_html` 둘뿐이다. 그 밖의 모든 문자열
  (주제, 프롬프트, 이벤트 메시지, 문헌 제목·초록·저자, 오류 메시지)은 `textContent`/DOM 생성으로만 넣는다.
  외부 링크는 `http(s)`로 시작할 때만 `href`에 넣고 `target="_blank" rel="noopener noreferrer"`를 붙인다.
- API 키: 기본은 메모리 + `sessionStorage`(탭을 닫으면 사라짐). "이 브라우저에 저장"을 켠 경우에만 `localStorage`.
  키는 요청 본문으로만 보낸다(URL·로그 금지). 화면에는 끝 4자리만 보여 준다.
- 한국어 UI. `lang="ko"`, `word-break: keep-all`.

## 2. 파일 구성

```
web/index.html
web/assets/app.css             # 토큰 + 공통 컴포넌트 + 화면별 스타일
web/assets/js/main.js          # 시작점: 설정 로드, 라우터, 테마
web/assets/js/api.js           # fetch 래퍼(오류를 {code, message}로 통일), 다운로드 헬퍼
web/assets/js/store.js         # 상태(설정, 키, 기록, 현재 실행) + 구독
web/assets/js/ui.js            # DOM 헬퍼 h(), 아이콘(SVG), 토스트, 모달, 팝오버, 숫자·시간 포맷
web/assets/js/views/compose.js # 작성 화면
web/assets/js/views/run.js     # 진행 화면
web/assets/js/views/result.js  # 결과 화면(탭 5개)
web/assets/js/charts.js        # 막대·분할 막대 차트(SVG/CSS)
```

라우팅은 해시 기반: `#/`(작성), `#/run/<id>`(상태에 따라 진행 또는 결과 화면), `#/run/<id>/<tab>`(`report|evidence|verify|process|qa`).

## 3. 공통 셸

- 왼쪽 사이드바: 워드마크, "새 조사" 버튼, **기록** 목록, 아래쪽에 API 키 상태 버튼과 테마 전환(라이트/다크/시스템).
  900px 미만에서는 상단 바 + 서랍으로 접힌다.
- 기록 항목: 상태 점(진행 중은 움직임), 주제(2줄까지), 보조 줄(모델 · 소요 시간 · 채택 n건 / 진행 중이면 현재 단계).
  샘플은 "샘플" 태그, 데모 실행은 "데모" 태그. 항목 메뉴: 삭제(확인 후 `DELETE`), 샘플은 삭제 불가.
  진행 중인 실행이 있으면 10초마다 `GET /api/runs`로 갱신한다.
- 데모 모드(`config.demo`)면 화면 위에 얇은 안내 띠: "데모 모드 — 기록된 실제 실행을 재생합니다. API를 호출하지 않으며 비용이 들지 않습니다."
- API 키 창(모달 또는 팝오버): 입력(비밀번호형, 보기 전환), "확인"(`POST /api/key/check`), "이 브라우저에 저장" 체크, "지우기".
  상태: 없음 / 미확인 / 확인됨(사용 가능 모델 수) / 오류(메시지). `config.server_key`면 "서버에 설정된 키를 사용합니다"를 보여 주고 입력은 선택.
- 서버 연결 실패 시 상단에 "서버에 연결할 수 없습니다. 다시 시도" 띠.
- 토스트: 성공/오류 알림. `aria-live="polite"`.

## 4. 작성 화면 (`#/`)

1. **프롬프트**: 큰 입력창(자동 높이, 최대 4000자, 글자 수 표시), 자리표시 "연구 주제나 궁금한 점을 적어 주세요. 범위·기간·강조할 점을 함께 적어도 됩니다."
   아래에 `config.examples` 칩(누르면 입력창에 채움). 작성 중인 글은 `localStorage`에 임시 저장. `Ctrl+Enter`로 시작.
2. **모델**: `config.models` 카드형 단일 선택(이름, 한 줄 설명, 100만 토큰당 입력·출력 가격, 배지). 키 확인 결과에 없는 모델은
   "이 키로 사용 불가"로 표시하고 선택을 막는다. 설명(`description`)은 툴팁/보조 문구로.
3. **조사 깊이**: `config.depths` 단일 선택(이름, 설명, 예상 시간).
4. **결과물**: `config.formats`를 그룹별 다중 선택 칩으로(보고서 / 발표 / 참고문헌·데이터). `available=false`면 `note`를 보여 주되 선택은 허용
   (PDF는 인쇄 창으로 대체된다고 안내). 최소 1개.
5. **옵션**: "조사 계획을 먼저 검토하기" 스위치(+설명), "고급 설정" 접이식 —
   검색 시작 연도(에이전트가 결정 / 제한 없음 / 직접 입력), 보고서 언어(자동/한국어/영어), 재조사 횟수, 하위 질문당 검색 라운드,
   검색 1회당 문헌 수, 인용 검증 문장 수, 병렬 실행 수. 범위는 `config.limits`, 기본값은 선택한 깊이의 `config`.
   깊이를 바꾸면 고급 설정 값이 그 프리셋으로 갱신된다(사용자가 고친 값은 "직접 설정" 표시와 함께 유지).
6. **예상치**: `선택한 깊이의 estimate × 선택한 모델 가격`으로 "LLM 호출 약 n회 · a~b분 · 예상 비용 약 $x"를 보여 준다.
   `estimate.measured`가 false면 "(추정)"을, true면 "(실제 실행 2회 평균 기준)"을 덧붙인다. 가격 기준일 `config.pricing_as_of` 표기.
7. **조사 시작**: 검증(프롬프트 비어 있음, 키 없음 — 데모/서버 키면 통과) → `POST /api/runs` → `#/run/<id>`로 이동.
   서버 오류는 해당 입력 아래에 표시. 마지막으로 쓴 모델·깊이·형식·옵션은 `localStorage`에 기억한다.
8. "같은 설정으로 다시 조사"로 들어오면 그 실행의 `prompt`와 `config`로 채운다.

## 5. 진행 화면 (`#/run/<id>`, 상태가 queued/running/awaiting_plan일 때)

- **머리**: 주제, 모델 칩, 경과 시간(1초마다 갱신), "중단" 버튼(확인 후 `POST …/cancel`).
- **단계 표시**: `config.stages` 8개. `status.stage`로 완료/진행/대기를 나누고, `status.round ≥ 2`면 "재조사 라운드 n" 표시와
  ⑥→③ 되돌아가는 흐름을 드러낸다. 진행 중인 단계에는 `status.progress`(done/total, label)를 진행 막대로.
- **카운터**: 수집, 채택, 중복 병합, LLM 호출, 토큰(입력/출력), 예상 비용(`cost_usd`가 null이면 "—").
- **조사 계획 카드**: `status.plan.sub_questions`. 각 질문의 상태를 이벤트로 계산한다 —
  `tool`/`tool_error` 이벤트의 `data.subq`가 나오면 "탐색 중", `subq_done`이면 "탐색 완료 · 후보 n건", `synthesis`면 "종합 완료 · 근거 강도".
  재계획으로 추가된 질문은 "추가됨" 표시.
- **활동 기록**: 이벤트를 최신순으로. kind별 표현 —
  `tool`: DB 이름(`config.tools`의 label) + 검색어 + 결과 수(조용한 한 줄), `tool_error`: 흐린 오류 줄, `tool_disabled`/`warning`: 경고 줄,
  `subq_done`·`evaluate`·`synthesis`·`report`·`verify`·`repair`: 요약 줄, `understanding`/`window`/`plan`: 강조 줄,
  `reflection`: 카드(라운드, 품질 점수/10, 계속 여부, 이유, 편향 위험 목록), `replan`: 새 하위 질문/추가 검색.
  `data`가 없으면 `msg`만 보여 준다. 같은 하위 질문의 연속된 `tool` 줄은 접어서 "검색 n건" 묶음으로 보여 줘도 된다. DOM은 최근 250개까지만 유지.
- **보고서 미리보기**: `stage == "report"`이고 `preview`가 오면 "보고서 작성 중" 패널에 텍스트를 이어 붙인다(자동 스크롤).
  미리보기는 원문 텍스트이므로 `textContent`로 넣고, 줄 단위로 `#`/`-`만 가볍게 꾸민다.
- **계획 검토**(`status.awaiting == "plan"`): 계획 카드가 편집 가능해진다 — 질문 문장 수정, 삭제, 추가(최대 8개), 의견 입력란.
  "승인하고 진행"(`{"action":"approve"}` 또는 수정했으면 `sub_questions` 포함), "의견 반영해 다시 계획"(`{"action":"revise","feedback":…}`).
  대기 중임을 분명히 보여 주고(단계 표시에 "검토 대기"), 브라우저 탭 제목에도 표시한다.
- **종료 처리**: `done` → 결과 화면으로 전환(탭 제목 "조사 완료 — …", 토스트). `error` → 오류 메시지와 "설정을 고쳐 다시 시도" 버튼.
  `cancelled`/`interrupted` → 안내와 "다시 조사" 버튼. 그때까지의 활동 기록은 계속 볼 수 있다.

## 6. 결과 화면 (`status == "done"`)

`GET /api/runs/{id}/result`를 한 번 받아 모든 탭이 공유한다.

- **머리**: 주제, 메타 줄(모델 · n분 · 수집 a / 채택 b · LLM 호출 c회 · 약 $d · 검색 기간), 샘플/데모면 `meta.note`.
  **내려받기**: 실행 때 고른 형식은 버튼으로, 나머지는 "다른 형식" 메뉴로(`config.formats` 전부 + ZIP).
  내려받기는 `fetch` → Blob → 저장(파일명은 `Content-Disposition`의 `filename*`에서). 생성 중에는 버튼에 진행 표시.
  PDF가 `409 pdf_unavailable`이면 `…/export/html?print=1`을 새 탭으로 열고 "인쇄 창에서 'PDF로 저장'을 선택하세요" 안내.
  "같은 설정으로 다시 조사", "Markdown 복사" 동작.
- **탭 1 보고서**: 왼쪽(넓은 화면) 목차(`toc`, 스크롤 위치 강조), 본문은 `report_html`. 본문의 `a.cite`는 **인용 칩** —
  호버·포커스·클릭 시 출처 카드(ID, 저자·연도, 제목, 학술지, 유형/연구 설계/방향 배지, 점수, 피인용, 핵심 결과, "원문 열기", "근거 탭에서 보기").
  칩 클릭의 기본 동작(`#ref-…` 이동)은 막는다. `Esc`로 닫힘. "인쇄용으로 열기"(`…/export/html?inline=1`).
- **탭 2 근거**: 숫자 타일(수집, 채택, 중복 병합, 본문 인용) → 차트(연구 유형: 한 색상의 순위 가로 막대 / 결과 방향: 분할 막대 1개 + 범례 /
  출판 연도: 세로 막대 / 출판 유형: 순위 막대) → 필터(검색어, 채택만·전체, 출판 유형, 연구 설계, 방향, 하위 질문, 인용된 것만) →
  표(ID, 문헌(저자·연도·제목·학술지), 유형, 설계, 방향, 점수, 피인용, 인용 여부; 점수·연도·피인용 정렬). 행을 누르면 상세 패널
  (초록, 방법, 표본, 핵심 결과, 한계, 관련 하위 질문, 찾은 검색어, 원문 링크). 기본은 "채택만" + 점수순.
- **탭 3 검증**: 요약(인용 ID 수, 인용 문장 수, 검증 문장 수, 제거된 미존재 ID), 판정 집계 **수정 전 → 수정 후**, 문장 카드 목록
  (판정 배지, 문장, 검증 메모, 수정됐으면 수정문과 재검증 판정). 검증이 표본 검사임을 한 줄로 밝힌다.
- **탭 4 과정**: ① 주제 이해(분야, 연구 유형, 핵심 개념, 변수, 모호성과 범위 결정, 검색 기간과 이유, 사용자 요구) /
  ② 조사 계획(하위 질문별 관점·이유·검색어·도구, 채택 문헌 수, 근거 강도; 펼치면 종합 답변·핵심 발견·합의/충돌·공백) /
  ⑥ 자기 비판(라운드별 점수, 이유, 편향 위험, 추가 검색, 새 하위 질문) / 수행 기록 타임라인(`trace`) + "전체 이벤트 보기"(events API).
- **탭 5 질문하기**: 이 조사의 근거에만 기반해 답하는 대화. 추천 질문 3개, 입력창, 답변은 `answer_html`(인용 칩 동일) + 근거 목록.
  기록은 `result.qa`. 키가 필요하면(데모·서버 키 아님) 키 창으로 유도. 답변 대기 중 표시, 오류는 대화 안에 표시.

## 7. 차트 규칙 (`charts.js`)

데이터 시각화 지침(Anthropic dataviz 스킬)을 따른다:
- 형식 먼저, 색은 마지막. 크기 비교는 **한 색상**의 순위 막대(큰 값부터, 8개 초과는 "기타"로 합침), 구성비는 **분할 막대 1개 + 범례**.
  원형·도넛 차트, 이중 축, 무지개 색 금지.
- 막대는 얇게(높이 10~14px), 끝은 4px 둥글게, 막대 사이 2px 이상 간격, 값 레이블은 막대 옆에 텍스트 색으로(계열 색으로 글자를 칠하지 않는다).
- 2개 이상 계열에는 범례 필수. 각 막대/조각에 호버 툴팁(이름, 값, 비율). 표 보기로도 같은 정보를 확인할 수 있어야 한다.
- 상태색(지지/부분 지지/상충)은 판정 표시에만 쓰고 계열 색으로 재사용하지 않는다. 판정은 색 + 아이콘 + 글자로 함께 표시.
- 다크 모드는 뒤집기가 아니라 별도 선택 값.

## 8. 접근성 · 품질

- 랜드마크(`nav`, `main`), 현재 항목 `aria-current`, 탭은 `role="tablist"`와 화살표 키 이동, 모달은 포커스 가두기와 `Esc` 닫기.
- 모든 컨트롤에 보이는 포커스 링, 최소 32px 터치 영역, 텍스트 대비 4.5:1 이상, `prefers-reduced-motion` 존중.
- 로딩에는 스켈레톤, 빈 상태에는 다음 행동을 알려 주는 문구.
- 820px 폭에서 가로 스크롤이 없어야 하고, 1280×800과 1440×900에서 구도가 잡혀야 한다.

## 9. 디자인 시스템

**방향: "조용하고 정확한 연구 도구".** 논문을 읽고 쓰는 사람이 오래 켜 두는 화면이다. 차분한 중립 회색 면, 진한 잉크색 글자,
강조색은 코발트 블루 한 가지. 장식보다 정렬·간격·위계로 완성도를 만든다. Linear·Vercel 대시보드 같은 전문 도구의 밀도와 선명함에,
보고서 본문만은 잡지처럼 넉넉한 행간으로 읽기 편하게.

금지: 보라-파랑 그러데이션, 유리 효과(blur), 이모지 아이콘, 색을 여러 개 쓰는 장식, 그림자 남용, 가운데 정렬된 긴 글.

### 9.1 토큰
`web/assets/tokens.css`가 단일 원본이다(이미 작성됨, 값 변경 금지). `app.css`는 색·간격·글꼴을 **반드시 토큰으로만** 쓴다(16진수 직접 사용 금지).
테마는 `<html data-theme="light|dark">`, 속성이 없으면 OS 설정을 따른다. 사용자가 고른 테마는 `localStorage`에 저장한다.

### 9.2 타이포그래피
- UI 기본 14px/1.5, 보조 13px, 캡션 12px(이보다 작게 쓰지 않는다). 화면 제목 28px/700, 섹션 제목 15px/600, 카드 제목 14px/600.
- 숫자를 비교하는 곳(카운터, 표, 가격, 타이머)은 `font-variant-numeric: tabular-nums`.
- 검색어·ID·시각·토큰 수 같은 "기계가 만든 값"은 `--font-mono` 12~13px.
- **보고서 본문**: 16px/1.8, 읽기 폭 `--read-w`(760px), `word-break: keep-all`, 문단 사이 0.9em.
  h1 26px/700(위 여백 없음), h2 20px/700(위 2.2em, 아래 얇은 구분선), h3 16.5px/700, 목록 들여쓰기 1.3em, 굵은 글씨는 `--text` 그대로 600.
  표: 13.5px, 머리글 `--surface-2` 배경 + 600, 칸 여백 8px 10px, 바깥 테두리 없이 가로줄만, 넓으면 표만 가로 스크롤.
- 웹폰트: Pretendard(jsDelivr `cdn.jsdelivr.net/gh/orioncactus/pretendard`의 variable dynamic subset CSS)를 `<link>`로 불러오되 실패해도 시스템 글꼴로 자연스럽게.

### 9.3 구성 요소
- **버튼**: 높이 36px(주 실행 버튼만 44px), 모서리 `--r-md`, 글자 14px/600. 주(primary) = `--accent` 배경 + `--text-on-accent`,
  보조 = `--surface` + 1px `--border-strong`, 유령(ghost) = 배경 없음. 호버·눌림·비활성·진행 중(스피너) 상태를 모두 만든다.
  포커스 링: `outline: 2px solid var(--accent); outline-offset: 2px`(모든 포커스 가능 요소 공통, `:focus-visible`).
- **선택 카드**(모델·깊이): `--surface`, 1px `--border`, 모서리 `--r-lg`, 여백 14px 16px. 선택됨 = 1.5px `--accent` 테두리 + `--accent-soft` 배경 +
  오른쪽 위 체크 아이콘. 실제 `<input type="radio">`를 시각적으로 숨기고 `<label>` 전체를 누를 수 있게 한다.
- **칩**(형식 선택·예시): 높이 30~32px, 알약 모양, 1px 테두리. 선택됨 = `--accent-soft` 배경 + `--accent` 글자·테두리 + 체크.
- **배지**: 높이 20px, 12px/600, 옅은 배경. 판정 배지는 아이콘 + 한국어 라벨: 지지(✓, good) / 부분 지지(물결, warning) / 초록에 없음(−, neutral) / 상충(×, critical).
  출판 유형·연구 설계 배지는 중립색. 방향은 글자 + 작은 기호(▲ 긍정, ▼ 부정, ◆ 혼재, ○ 효과 없음, – 해당 없음), 상태색을 쓰지 않는다.
- **카드**: `--surface`, 1px `--border`, 모서리 `--r-lg`, 그림자 없음(떠 있는 것 — 팝오버·모달·토스트 — 에만 그림자).
- **단계 표시(스테퍼)**: 가로 8칸. 원(28px) + 아래에 단계 이름(12.5px). 완료 = `--accent` 채움 + 흰 체크, 진행 중 = `--accent` 테두리 + 안쪽 점이 천천히 맥동 +
  아래에 얇은 진행 막대, 대기 = `--border-strong` 테두리 + 번호. 원 사이는 2px 선(완료 구간은 `--accent`). ⑥에서 ③으로 돌아가는 흐름은
  스테퍼 아래에 가는 꺾은선 화살표와 "근거가 부족하면 재조사" 라벨로 표현하고, 재조사 중이면 그 선을 `--accent`로 바꾸고 "라운드 2" 배지를 붙인다.
  820px 이하에서는 원만 남기고 이름은 현재 단계만 보여 준다.
- **카운터 타일**: 라벨(12px, `--text-3`) 위, 값(22px/700, tabular) 아래. 2×3 격자. 값이 바뀌면 짧게 강조(배경이 살짝 밝아졌다 돌아옴).
- **활동 기록 줄**: `시각(mono 12px, --text-3) · 단계 태그 · 내용`. 도구 호출 줄은 한 줄로 조용하게(DB 라벨 칩 + mono 검색어 + "→ 6건"),
  오류 줄은 `--text-3` + 작은 경고 아이콘, 요약 줄(탐색 완료·평가·종합·검증)은 `--text` 600, 자기 비판은 카드(왼쪽에 3px `--accent` 세로줄, 점수는 큰 숫자).
  새 줄은 위에서 부드럽게 나타난다(180ms).
- **탭**: 밑줄형. 활성 탭 = `--text` 600 + 2px `--accent` 밑줄. 탭 줄은 결과 화면에서 위에 붙는다(sticky).
- **표**(근거): 머리글 고정(sticky), 13px, 행 높이 44px 이상, 행 호버 `--surface-2`, 정렬 가능한 머리글에 화살표. 선택된 행은 `--accent-soft`.
- **인용 칩**(`a.cite`): 본문 글자보다 조금 작은 mono 12.5px, `--accent` 글자, `--accent-soft` 배경, 모서리 4px, 좌우 여백 4px, 밑줄 없음. 호버 시 진해짐.
- **출처 카드(팝오버)**: 폭 360px, `--surface`, 모서리 `--r-lg`, `--shadow-pop`. 위에서부터 `S55 · 동료심사 · RCT/실험` 배지 줄, 제목(14px/600, 3줄까지),
  저자·연도·학술지(13px, `--text-2`), 핵심 결과(13.5px, 왼쪽 2px 세로줄), 아래 메타(방향, 점수, 피인용)와 동작 2개.
  화면 밖으로 나가지 않게 위치를 보정한다.
- **입력**: 높이 36px, 1px `--border-strong`, 모서리 `--r-md`, 포커스 시 `--accent` 테두리 + 3px `--accent-ring`. 프롬프트 입력창은 테두리 카드 안에
  배경 없는 textarea(17px/1.6)로 넣고, 카드 전체가 포커스 링을 받는다.
- **스위치**: 36×20px, 켜짐 = `--accent`. `role="switch"`.
- **토스트**: 오른쪽 아래, `--text` 배경에 `--surface` 글자(반전), 4초 뒤 사라짐. **모달**: 가운데, 폭 440px, 뒤에 `--scrim`.
- **아이콘**: 16px 인라인 SVG, `stroke="currentColor"`, 선 굵기 1.5, 둥근 끝. 한 벌로 통일해 `ui.js`에 모은다.
- **움직임**: `--dur` 160ms, `--ease`. 화면 전환은 짧은 페이드. `prefers-reduced-motion: reduce`면 맥동·이동 효과를 끈다.

### 9.4 화면 구도
- **셸**: 사이드바 `--sidebar-w`(264px) 고정 + 본문. 사이드바는 `--surface`와 오른쪽 1px 테두리. 워드마크는 작은 사각 로고(강조색 바탕에 흰 기호) + "AI Research Agent" 15px/700.
  본문 바탕은 `--bg`.
- **작성**: 가운데 한 단(`--content-w` 860px). 위에서부터 큰 제목 "무엇을 조사할까요?"와 한 줄 설명 →
  프롬프트 카드(입력창 + 아래 줄에 예시 칩과 글자 수) → "모델" 4칸 격자(좁으면 2칸) → "조사 깊이" 3칸 → "결과물" 칩 그룹 → 옵션(스위치 + 고급 설정) →
  아래에 붙는 실행 줄(왼쪽에 예상치 문장, 오른쪽에 44px "조사 시작" 버튼; 스크롤해도 화면 아래에 고정, 위쪽에 얇은 테두리와 `--surface` 배경).
  섹션 사이 32px, 섹션 제목 왼쪽 정렬 15px/600 + 오른쪽에 12.5px 보조 설명.
- **진행**: 위에 머리 줄(주제 22px/700 두 줄까지, 모델 칩, 타이머, 중단) → 스테퍼 카드(가로 전체) → 2단(왼쪽 넓은 쪽: 조사 계획 카드, 활동 기록 /
  오른쪽 320px: 카운터 타일, "지금 하는 일" 카드, 자기 비판 카드들). 1100px 미만은 1단. 보고서 단계에서는 왼쪽 맨 위에 "보고서 작성 중" 미리보기 패널이 나타난다.
- **결과**: 머리(주제, 메타 줄, 내려받기 버튼들) → 탭 줄 → 탭 내용. 보고서 탭은 왼쪽 목차 220px(스크롤 따라 고정) + 본문 760px, 가운데 정렬.
  1000px 미만에서는 목차를 접이식으로 본문 위에 둔다. 근거 탭은 타일 4개 → 차트 2×2 카드 → 필터 줄 → 표(+ 오른쪽 상세 패널 380px, 좁으면 아래로).

### 9.5 차트 색
크기 비교 막대는 `--chart-seq` 한 색. "결과 방향" 분할 막대는 대상에 색을 고정한다 — 긍정 `--chart-1`, 부정 `--chart-2`, 혼재 `--chart-3`,
효과 없음 `--chart-4`, 해당 없음·미분류 `--chart-none`. 이 4색은 색각 이상 구분 검증(dataviz validator)을 라이트·다크 모두 통과했다.
라이트에서 `--chart-3`·`--chart-4`는 배경 대비가 3:1 미만이므로 **조각 위/옆의 글자 라벨과 범례, 표 보기가 반드시 함께** 있어야 한다.
막대 위 글자는 계열 색이 아니라 `--text`/`--text-2`로 쓴다.
